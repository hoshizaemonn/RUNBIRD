03 ― なぜ Cursor + GitHub なのか（他ツールとの比較）

6つの候補を検討した結果、福祉事業の法規制対応には Cursor + GitHub が最適と判断

評価軸 Cursor
+GitHub		 ChatGPT
Team		 Notion
AI		 Microsoft
Copilot		 Dify
AIが毎回ナレッジを読むか ◎ 必ず△ ムラあり○○◎
変更履歴の完全性 ◎ 完全✕ なし○ 90日○△
誤った変更を元に戻せるか ◎✕○○△
県別の法規制を分けて管理 ◎△ 上限あり○○○
返信文の自動生成品質 ◎○○○◎
非技術者の操作しやすさ ○○◎◎○
コスト（5人/月） 約1.5万円約2万円約1.8万円約2.8万円API代のみ
Cursor + GitHub を選ぶ決定的理由：
1️⃣ AIが毎回必ずナレッジを全文読む — 他ツールはAI検索（RAG）で関連文書を「探す」方式のため見落としが起きる。福祉の法規制は「見落とし＝事故」なので、確実性が最重要
2️⃣ 変更履歴が永久に残る — 「いつ・誰が・どのルールを変えたか」を完全追跡。行政指導・監査時に「当時のナレッジ状態」を証明できる。Notion の90日履歴では不十分
3️⃣ 誤変更を即座に巻き戻せる — 間違った法令情報がナレッジに入っても1クリックで元に戻せる

05 ― ナレッジに何を入れるか
返信例（前田さん等ベテランの返信パターン）
利用者家族への日常連絡・スケジュール調整
苦情・相談への対応（受付→改善報告）
他施設への紹介・受入れ打診・引継ぎ
行政への報告書（事故報告・変更届等）
サービス担当者会議の招集・議事録
※チャットワークの過去ログを読み込んで、前田さんの返信例をナレッジ化する
触れてはいけないライン（法令ガードレール）
職員が医学的判断・診断名を伝える → NG
支給決定の可否を断言する → NG（決定権は行政）
他の利用者の状況を引き合いに出す → NG
本人同意なく第三者に個人情報開示 → NG
虐待の疑い「様子見」 → NG（即時通報義務）
※AIがこれらの表現を使おうとした場合、自動でブロックする仕組み
法令・制度（県ごとに異なるもの）
人員配置基準の解釈（常勤換算の計算等）
事故報告書の様式・報告基準
加算届の提出期限・添付書類
送迎範囲・設備基準の上乗せ規制
支給量の基準（同じ区分でも自治体で異なる）
※県・市ごとにファイルを分けて管理。法改正時は該当ファイルを更新するだけ
事業所・契約ごとのルール
各事業所の契約条件・サービス内容
報酬算定の地域区分（1級地〜7級地）
処遇改善加算の計画内容
BCP（業務継続計画）の内容
第三者評価の受審状況
※事業所が増えたらファイルを追加するだけでAIが対応可能に
06 ― 全員がうまく使い続けるための仕組み

🗂️ フォルダ構成を固定する

「返信例/」「法令/」「事業所/」の分類を最初に決めて固定

置き場所がバラバラだとAIが見つけられなくなる → フォルダ名と分類ルールを統一

✅ レビューしてから反映

ナレッジの変更は管理者が確認してから反映する

間違った法令情報がAIに入ると危険 → 変更は提案→管理者チェック→反映

📝 書き方のテンプレを統一

全員が同じフォーマットで書く。AIの理解精度が上がる

書き方がバラバラだとAIの出力品質が下がる → テンプレートに沿って書くだけにする

🔄 月1回の棚卸し

法改正の反映漏れがないか定期チェック

放置すると古い法令でAIが回答してしまう → 定期的な見直しをルール化
フォルダ固定 + レビュー制 + テンプレ統一 + 月次棚卸し
この4つのルールで、誰が触っても崩れないナレッジ基盤になる
